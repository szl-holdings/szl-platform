# SZL Position — draft-sharif-agent-audit-trail-09

**Date:** 2026-11-17
**Draft:** [Agent Audit Trail: A Standard Logging Format for Autonomous AI Systems](https://datatracker.ietf.org/doc/draft-sharif-agent-audit-trail/) — R. Sharif, CyberSecAI Ltd, revision -09 (2026-10-26), individual submission, no working group.
**Position:** SUPPORT WITH REQUIRED CHANGES.

## Findings driving the position

Revision -09 tightens trust-level handling but preserves the structural gap
flagged since the low-trust tiers were introduced: at low trust levels the
agent itself writes the on-behalf-of principal field, so the record attests
its own mandate. Independent analysis of the -06→-09 trust tiers reached the
same conclusion ([IAM Insights](https://insights.bostonidentity.com/research/ietf-datatracker-2026-09-29-agent-audit-trail-standard)).

## Required changes

1. **Envelope the records.** Wrap each audit record in a DSSE-style envelope
   (RFC 9052/COSE-compatible) so verification is over the exact signed bytes.
   Bare signed JSON permits payload/signature substitution.
2. **Chain the records.** Each record SHOULD carry the digest of its
   predecessor, with periodic signed Merkle checkpoints (RFC 6962-style
   signed tree heads). This converts the trail from tamper-*resistant* to
   tamper-*evident* against the log keeper itself.
3. **Guarantee offline verification.** Normative language that an exported
   Audit Trail verifies with no access to the producing system or any online
   service.
4. **Close the low-trust self-attestation gap.** The on-behalf-of principal
   field MUST either be signed by a principal at a higher assurance level,
   witness-countersigned, or explicitly labeled unverifiable — never
   presented as evidence.

## Recommended extension

**Memory governance.** AAT records agent *actions*; agent *memory* is
outside its scope. SZL recommends a memory-governance extension in which
writes to and recalls from persistent memory are first-class audit events.
The [Memory Covenant](https://github.com/szl-holdings/szl-frontier/tree/main/covenant-spec)
is a running-code reference for this extension: deny-by-default governed
memory plane, DSSE envelopes, hash-chained receipts, witness countersigning,
and a Lean-verified monotonicity lemma (approval cannot lift a hard deny).
