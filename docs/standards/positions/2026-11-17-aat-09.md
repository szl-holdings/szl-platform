# SZL Position — draft-sharif-agent-audit-trail-09

**Date:** 2026-11-17 (revised same day after full-text review of -09)
**Draft:** [Agent Audit Trail: A Standard Logging Format for Autonomous AI Systems](https://datatracker.ietf.org/doc/draft-sharif-agent-audit-trail/) — R. Sharif, CyberSecAI Ltd, revision -09 (2026-10-26), individual submission, no working group.
**Position:** SUPPORT — convergence acknowledged; extensions requested.

## Convergence with SZL's earlier filed positions

The -04→-09 revision range adopted the substance of the positions SZL
filed earlier against this draft:

- **Chain digests** — Section 6: mandatory tamper-evident hash chaining
  (SHA-256, JCS per RFC 8785, `prev_hash` over the complete previous
  record), gap-free `sequence_number`, genesis records, and
  `prior_generation_tail` continuity across key rotation/migration.
- **Signature envelope** — Section 6.2: detached signature-value fields over
  JCS-canonicalized records, `signer_kid`, hybrid classical +
  post-quantum signing mode.
- **Merkle checkpoints** — Section 6.4: optional batch anchoring using the
  RFC 6962 construction, detached from the chain hash.
- **Offline verification** — demonstrated by the reference implementation
  (aat-mcp) and a third-party offline verifier, both listed in the draft.
- **Recording independence** — Section 5: graded levels (self-recording only
  at L0/L1, independent recorder required at L2+), trust-level assignment
  integrity (5.3), optional hardware-attested tier (5.4, RATS RFC 9334
  composition).
- **SCITT interop** — session hash / Merkle root MAY be registered with a
  SCITT transparency service as external anchor.

SZL's earlier "required changes" (envelopes, chain digests, offline
verification) are therefore retired; the convergence is recorded explicitly.

## Requested extensions

1. **Normative offline verification.** Exported trails MUST verify with no
   access to the producing system or any online service. Today this exists
   in implementations but not as draft language.
2. **Tie anchoring strength to recording level.** Merkle batch anchoring /
   external anchoring (SCITT registration) and signatures are OPTIONAL
   (`MAY`). For L2+ or high-consequence actions they SHOULD be required;
   otherwise the strongest properties remain opt-in.
3. **Envelope-carriage profile.** The draft notes AAT records MAY be
   carried in DSSE-style envelopes. A registered payload-type / carriage
   profile would make that interoperable rather than ad hoc.
4. **Memory-governance extension.** The one standing gap: AAT records agent
   actions; agent *memory* appears only in passing. Writes to and recalls
   from persistent memory are audit events of equal standing. SZL offers
   the [Memory Covenant](https://github.com/szl-holdings/szl-frontier/tree/main/covenant-spec)
   as a running-code reference: deny-by-default governed memory plane, DSSE
   envelopes, hash-chained receipts, BFT witness countersigning, and a
   Lean-verified monotonicity lemma (an approval cannot lift a hard deny).
